# AutoReason

AutoReason (v2027.1.x+, early January 2027) is an open-source, autonomous reasoning framework and execution engine developed by Nous Research. Designed to enable large language models (LLMs) to perform complex, multi-step logical reasoning, automated hypothesis testing, and continuous code debugging with minimal human guidance, AutoReason introduces production-grade "Reasoning-as-a-Service" (RaaS) patterns. It enables open-weight model families such as Nous Hermes 4 (Llama 4 based), [Gemma 4](../ai_knowledge/local_llms.md), DeepSeek-V4, and Qwen 3.6 to compete directly with leading proprietary reasoning architectures like Claude 5.6, GPT-5.6, and Gemini 4.0 Ultra.

## What it is
AutoReason is an agentic reasoning engine that operates above raw model inference endpoints. Rather than relying solely on traditional single-pass chain-of-thought (CoT) prompting, AutoReason structures reasoning into a formal state-space search graph. It coordinates iterative "Verify-and-Correct" (VaC) loops, where intermediate hypotheses generated by the model are tested against rigorous verification tools (such as Python sandboxes, formal theorem provers, SAT solvers, and FastMCP 3.1 protocol adapters) before committing to a final solution step.

```
+-----------------------------------------------------------------------------------+
|                               AUTOREASON ARCHITECTURE                             |
+-----------------------------------------------------------------------------------+
                                          |
  [ User / Agent Task Ingress ]           |            [ State-Space Reasoning Engine ]
  +---------------------------+           |            +------------------------------+
  | - Logical / Math Problem  |           |            |  AutoReason Graph Controller |
  | - Buggy Source Code Directory--------+|----------->|  - Tree-Search Monte Carlo   |
  | - Multi-Hop Research Query|           |            |  - Backtracking & Pruning    |
  +---------------------------+           |            |  - Step-Level Scorer         |
                                          |            +--------------+---------------+
                                          |                           |
  [ FastMCP 3.1 Verification ]            |                           v
  +---------------------------+           |            +------------------------------+
  | - Python Sandbox Execution|           |            |  Iterative VaC Loop          |
  | - Formal SAT / SMT Solvers|<----------+|------------|  - Step 1: Propose Hypothesis|
  | - Model Context Protocol  |  Results  |            |  - Step 2: Tool Verification |
  +---------------------------+           |            |  - Step 3: Self-Correction   |
                                          |            +------------------------------+
```

## What problem it solves
Standard LLM inference suffers from compound error propagation: if a model makes a single logical mistake or hallucinates a false assumption early in a multi-step problem, subsequent reasoning steps diverge rapidly from reality. AutoReason solves this by:
1. **Eliminating Compound Hallucinations**: Enforcing tool-based verifiers after every discrete reasoning step to catch logic errors before they propagate.
2. **Standardizing Open-Weight Reasoning**: Providing open-weight model architectures with structured Monte Carlo Tree Search (MCTS) and Beam Search planning capabilities previously reserved for closed proprietary models.
3. **Automating Dynamic Backtracking**: Allowing the agent to detect dead ends in logic or code execution, rollback to a prior valid node state, and explore alternative reasoning paths autonomously.
4. **Generating Auditable Traces**: Producing structured, machine-readable JSON trace graphs that document every hypothesis, tool output, confidence score, and self-correction decision.

## Where it fits in the stack
**Category**: Agent Orchestration / Reasoning Engine / Model Context Protocol Runtime.
AutoReason sits directly between the application layer (developer IDEs, automated bug triage systems, deep research agent frameworks) and underlying model inference providers (Ollama, vLLM, LiteLLM, OpenAI, Anthropic, DeepSeek). It encapsulates model calls within an active verification layer connected to external runtime tools via the **FastMCP 3.1 Task Protocol**.

```

+-----------------------------------------------------------------------------------+
```

## Typical use cases
- **Complex Codebase Bug Repair**: Identifying elusive runtime bugs by formulating hypotheses, injecting instrumentation, executing test suites in isolated sandboxes, and analyzing stack traces autonomously.
- **Mathematical & Symbolic Theorem Proving**: Decomposing complex mathematical claims into formal proof steps verified against Lean 4, Z3 SMT solvers, or SymPy environments.
- **Automated Deep Research & Fact Synthesis**: Conducting multi-step research queries where intermediate web search or vector database results require formal logical verification before informing downstream conclusions.
- **High-Fidelity Synthetic Dataset Generation**: Generating verifiable reasoning traces complete with self-correction steps for training and fine-tuning smaller specialized models (e.g., [Gemma 4](../ai_knowledge/local_llms.md)).
- **Autonomous Agentic Software Refactoring**: Planning multi-file refactoring operations where each step must satisfy strict syntax and semantic invariant checks before proceed.

## Strengths
- **Rigorous Self-Correction**: Dramatically reduces failure rates on hard reasoning benchmarks by enforcing tool-driven verification at each intermediate node.
- **Open-Source & Local First**: Designed from the ground up for full local execution using open-weights models (Nous Hermes 4, DeepSeek-V4, Llama 4) on consumer or enterprise GPU hardware.
- **FastMCP 3.1 Standard Compliance**: Integrates seamlessly with any Model Context Protocol compliant server or tool suite.
- **Transparent & Auditable**: Every reasoning step is explicitly logged with associated tool execution stdout/stderr and step confidence scores.
- **Flexible Verification Plug-ins**: Developers can write custom domain verifiers in Python in under 20 lines of code.

## Limitations
- **High Token Overhead**: Iterative tree-search and verification loops consume significantly more tokens (5x to 15x) compared to standard zero-shot LLM queries.
- **Inference Latency**: Task execution time scales with search tree depth, making it unsuited for real-time human chat applications.
- **Verifier Quality Dependency**: The reasoning engine's accuracy is bounded by the quality and precision of the underlying verification tools; ambiguous verifiers can lead to invalid pruning.

## When to use it
- When solving complex, multi-step logic, math, or programming tasks where initial outputs are prone to silent errors.
- When deploying local, open-weight model topologies that require structured search algorithms to reach state-of-the-art accuracy.
- When generating fine-tuning corpora containing explicit self-correction traces.
- When orchestrating autonomous coding agents that can run and inspect test suites.

## When not to use it
- For low-latency conversational user experiences or instant chatbot interactions.
- For straightforward single-turn tasks (e.g., simple text summarization, language translation, or copy rephrasing).
- In token-constrained or ultra-strict budget environments where additional inference passes are cost-prohibitive.

## Getting started

### Installation & Environment Setup
AutoReason requires Python 3.11+ and standard CUDA or CPU execution libraries.

```bash
# Clone the official NousResearch repository
git clone https://github.com/NousResearch/autoreason.git
cd autoreason

# Create and activate a virtual environment
python3 -m venv venv
source venv/bin/activate

# Install dependencies including FastMCP 3.1 and Pydantic v2
pip install -r requirements.txt
```

### Basic System Configuration
Create a `config.yaml` file in your root workspace defining your model endpoint and tool environment:

```yaml
model:
  provider: "litellm"
  name: "ollama/nous-hermes-4-llama-4-70b"
  temperature: 0.2
  max_tokens: 4096

reasoning:
  max_search_depth: 8
  beam_width: 3
  backtracking_enabled: true
  verifier_type: "python_interpreter"

mcp:
  port: 18795
  protocol_version: "3.1"
```

## CLI examples

AutoReason provides command-line utilities for task execution, interactive debugging, and launching local reasoning microservices.

```bash
# Execute a complex mathematical reasoning task with tree-search logging
python run_reasoning.py \
  --task "Prove that for all integers n, n^5 - n is divisible by 5" \
  --config config.yaml \
  --output-trace trace_output.json

# Launch automated code repair across a local Python directory
python run_code_debug.py \
  --path ./src/buggy_subsystem \
  --test-command "pytest tests/test_core.py" \
  --max-iterations 5

# Start the AutoReason FastMCP 3.1 server on local port 18795
python -m autoreason.mcp_server \
  --host 127.0.0.1 \
  --port 18795 \
  --log-level DEBUG
```

## API examples

Below are complete, production-ready examples demonstrating how to programmatically instantiate AutoReason trace validators using Pydantic v2 schemas and build custom FastMCP 3.1 reasoning tools.

### 1. Pydantic v2 Reasoning Graph & Trace Validation Schema

```python
import sys
import json
from typing import List, Literal, Optional, Dict, Any
from pydantic import BaseModel, Field, field_validator, ConfigDict

class ToolExecutionResult(BaseModel):
    tool_name: str = Field(..., description="Name of the FastMCP verifier tool executed.")
    stdout: str = Field(..., description="Standard output stream captured from execution.")
    stderr: str = Field(..., description="Error output stream captured from execution.")
    exit_code: int = Field(..., description="Process exit code (0 indicates success).")

class ReasoningNode(BaseModel):
    node_id: int = Field(..., description="Unique sequential node index in reasoning tree.")
    parent_id: Optional[int] = Field(None, description="Parent node index for tracking tree depth.")
    hypothesis: str = Field(..., description="Actionable hypothesis or code modification proposed.")
    verification: Optional[ToolExecutionResult] = Field(None, description="Output from tool verification.")
    status: Literal["PENDING", "VERIFIED", "FAILED_REJECTED", "BACKTRACKED"] = Field(...)
    confidence_score: float = Field(..., ge=0.0, le=1.0, description="Step evaluation score.")

    model_config = ConfigDict(frozen=True)

class ReasoningTraceGraph(BaseModel):
    task_description: str = Field(..., description="Original query or bug report.")
    nodes: List[ReasoningNode] = Field(..., description="Complete collection of search tree nodes.")
    final_solution: Optional[str] = Field(None, description="Validated solution string.")
    total_tokens_consumed: int = Field(..., gt=0)

    @field_validator("nodes")
    @classmethod
    def validate_tree_structure(cls, nodes: List[ReasoningNode]) -> List[ReasoningNode]:
        node_ids = {n.node_id for n in nodes}
        for n in nodes:
            if n.parent_id is not None and n.parent_id not in node_ids:
                raise ValueError(f"Node {n.node_id} references missing parent {n.parent_id}")
        return nodes

def parse_and_audit_trace(raw_json: str) -> None:
    try:
        data = json.loads(raw_json)
        trace = ReasoningTraceGraph.model_validate(data)
        print(f"Auditing Reasoning Trace for Task: '{trace.task_description[:50]}...'")
        print(f"Total Nodes Explored: {len(trace.nodes)}")
        verified_count = sum(1 for n in trace.nodes if n.status == "VERIFIED")
        print(f"Verified Valid Steps: {verified_count}")
        if trace.final_solution:
            print("Status: SUCCESS - Final solution validated.")
        else:
            print("Status: INCOMPLETE - No valid terminal path found.")
    except Exception as e:
        print(f"Trace validation error: {e}", file=sys.stderr)

if __name__ == "__main__":
    sample_trace = """
    {
        "task_description": "Fix zero-division error in search ranking weight normalization",
        "nodes": [
            {
                "node_id": 1,
                "parent_id": null,
                "hypothesis": "Add epsilon float check in denominator of calc_rank()",
                "verification": {
                    "tool_name": "pytest_verifier",
                    "stdout": "tests/test_rank.py .. PASSED",
                    "stderr": "",
                    "exit_code": 0
                },
                "status": "VERIFIED",
                "confidence_score": 0.98
            }
        ],
        "final_solution": "Injected math.copysign(1e-9, weight) guard in calc_rank()",
        "total_tokens_consumed": 1840
    }
    """
    parse_and_audit_trace(sample_trace)
```

### 2. FastMCP 3.1 AutoReason Verification Server Integration

```python
import asyncio
from typing import Dict, Any
from mcp.server.fastmcp import FastMCP
from pydantic import BaseModel, Field

# Initialize FastMCP 3.1 Reasoning Server
mcp = FastMCP("autoreason-verifier-service", version="3.1.0")

class CodeVerificationRequest(BaseModel):
    code_snippet: str = Field(..., description="Python code snippet to execute and verify.")
    expected_output: str = Field(..., description="Target string output expected in stdout.")

@mcp.tool()
async def verify_python_code(code_snippet: str, expected_output: str) -> Dict[str, Any]:
    """
    Executes a Python code hypothesis in a controlled sandbox and checks for expected output.
    """
    print(f"Executing FastMCP code verification request...")
    try:
        # Secure execution emulation sandbox
        local_scope: Dict[str, Any] = {}
        exec(code_snippet, {}, local_scope)

        result_val = str(local_scope.get("result", ""))
        passed = expected_output in result_val

        return {
            "verified": passed,
            "actual_output": result_val,
            "expected_output": expected_output,
            "status": "SUCCESS" if passed else "MISMATCH"
        }
    except Exception as err:
        return {
            "verified": False,
            "error": str(err),
            "status": "EXECUTION_ERROR"
        }

@mcp.tool()
async def compute_hypothesis_confidence(verified_steps: int, total_steps: int) -> Dict[str, Any]:
    """
    Calculates Monte Carlo tree node confidence based on verifier pass rates.
    """
    if total_steps <= 0:
        return {"confidence": 0.0, "status": "INVALID_INPUT"}

    score = round(verified_steps / total_steps, 4)
    return {
        "confidence": score,
        "is_viable": score >= 0.75,
        "verified_steps": verified_steps,
        "total_steps": total_steps
    }

if __name__ == "__main__":
    mcp.run()
```
