# Agentic Workbench

## What it is
Agentic Workbench is an enterprise-grade open-source control plane and visual orchestration platform for agentic workflows, multi-agent systems, and tool integration. Designed for seamless agent creation, monitoring, and live debugging, Agentic Workbench bridges low-level agent code with high-level operational visibility. It natively supports Model Context Protocol ([FastMCP 3.1](../automation_orchestration/mcp.md)) servers, distributed state persistence, real-time agent telemetry, and human-in-the-loop review queues across hybrid cloud and edge deployments.

## What problem it solves
Managing complex multi-agent systems with non-deterministic execution paths, tool-use loops, and context switching often leads to operational opacity, unmonitored agent drift, and difficult debugging. Agentic Workbench solves this problem by providing a unified operational dashboard, trajectory replay timeline, structured execution guardrails, and role-based access control (RBAC) for managing LLM agents at enterprise scale.

## Where it fits in the stack
**Agents / Control Plane & Multi-Agent Orchestration**. Agentic Workbench sits as the orchestration and observability layer above underlying LLM providers (such as [Claude 5.1](../ai_knowledge/claude.md) or [GPT-5.5](../ai_knowledge/openai.md)) and application interfaces (such as [LobeHub](../ai_knowledge/lobehub.md) or custom web applications), providing unified tool-calling policies and trace logging.

## Typical use cases
- **Multi-Agent Swarm Orchestration**: Coordinating specialized sub-agents for coding, document processing, and infrastructure auditing.
- **Enterprise Tool Policy Management**: Enforcing authorization, rate limits, and approval gates for MCP tool calls across company teams.
- **Agent Trajectory Debugging**: Intercepting agent tool calls, modifying intermediate state, and replaying failed tool invocations.
- **Human-In-The-Loop Approval Workflows**: Routing high-stakes financial or production deployment actions to human reviewers before execution.

## Strengths
- **Native FastMCP 3.1 Support**: Direct integration with FastMCP servers, tools, and resource providers without glue code.
- **Real-Time Trajectory Replay**: Interactive temporal view of agent thought chains, tool invocations, and environment feedback.
- **Strict Guardrails & Policies**: Integrated JSON schema and Pydantic validation for incoming and outgoing tool parameters.
- **Open Architecture**: Can be deployed via Docker, Kubernetes, or edge runtimes with full data residency compliance.

## Limitations
- **Operational Overhead**: Requires running dedicated control plane services (database, backend server, event bus) for full observability.
- **Storage Requirements**: Storing dense agent execution traces and media payloads requires persistent vector/time-series storage for long-running deployments.

## When to use it
- When managing multi-agent systems that require centralized administration, audit logging, and team collaboration.
- When building tool-augmented workflows where human authorization is required for critical execution branches.
- When running distributed agents across multiple cloud regions or hybrid environments.

## When not to use it
- For simple single-prompt LLM tasks or basic chatbots without tool-use requirements.
- For minimal local scripts where low resource consumption is prioritized over operational visibility.

## Getting started

### Installation
```bash
pip install agentic-workbench
```

### Quickstart CLI Execution
```bash
agentic-wb server start --port 8080 --mcp-config ./mcp_servers.json
```

## CLI examples

### Registering FastMCP Server and Inspecting Swarm
```bash
# Register an active FastMCP tool server
agentic-wb mcp register --name "document-processor" --url "http://localhost:8000/mcp"

# Inspect active agents and trace status
agentic-wb trace list --limit 10 --status active
```

## API examples

### Python Integration with Pydantic v2 Schema
The following Python script demonstrates how to define an agent task execution model, submit a request to the Agentic Workbench control plane, and validate the resulting execution trace using **Pydantic v2**:

```python
import os
from typing import List, Dict, Any, Optional
from pydantic import BaseModel, Field, ValidationError

class ToolInvocation(BaseModel):
    tool_name: str = Field(..., description="Name of the MCP tool called")
    parameters: Dict[str, Any] = Field(default_factory=dict, description="Input arguments passed to tool")
    output_summary: str = Field(..., description="Summarized output from the tool execution")

class AgentExecutionTrace(BaseModel):
    trace_id: str = Field(..., description="Unique trace identifier generated by Agentic Workbench")
    agent_name: str = Field(..., description="Target agent name")
    status: str = Field(..., description="Execution status: COMPLETED, FAILED, REQUIRES_APPROVAL")
    invocations: List[ToolInvocation] = Field(default_factory=list, description="Ordered list of tool invocations")
    confidence_score: float = Field(..., ge=0.0, le=1.0, description="Overall trace confidence score")

def submit_workbench_task(agent_name: str, prompt: str) -> AgentExecutionTrace:
    """Submits a task to Agentic Workbench control plane and validates the execution response."""
    # Simulated response from Agentic Workbench API
    raw_api_response = {
        "trace_id": "wb-trace-2027-8921",
        "agent_name": agent_name,
        "status": "COMPLETED",
        "invocations": [
            {
                "tool_name": "fetch_document",
                "parameters": {"doc_id": "doc-881"},
                "output_summary": "Retrieved 14 pages of technical documentation."
            },
            {
                "tool_name": "summarize_text",
                "parameters": {"max_tokens": 500},
                "output_summary": "Extracted key technical architecture components."
            }
        ],
        "confidence_score": 0.96
    }

    try:
        return AgentExecutionTrace.model_validate(raw_api_response)
    except ValidationError as e:
        print(f"Validation error parsing Workbench trace: {e}")
        raise

if __name__ == "__main__":
    trace = submit_workbench_task("research-agent", "Analyze recent architecture updates")
    print(f"Trace ID: {trace.trace_id} | Invocations: {len(trace.invocations)}")
    print(trace.model_dump_json(indent=2))
```
