# Claude Hooks

## What it is
Claude hooks are community patterns and JSON-based configurations that run around **Claude Code** sessions to add policy checks, notifications, automation, and guardrails. As of June 2026, they serve as the primary "middleware" for agentic coding, allowing for deterministic control over frontier models like **Claude 4.8 Opus**.

## What problem it solves
They let teams enforce workflow behavior outside the model prompt itself, which is often more reliable for guardrails and repetitive operational glue. They bridge the gap between an autonomous agent and the deterministic requirements of a production CI/CD pipeline, security policy, or linting standard.

## Where it fits in the stack
**Development & Ops / Workflow Guardrails**. Hooks sit around the coding-agent loop (Pre-execution and Post-execution) rather than inside the generated output. They are often integrated into the local development environment via `claude_config.json`.

## Typical use cases
- **Pre-Commit Linting**: Automatically running `eslint` or `prettier` before the agent considers a task "done".
- **Security Scanning**: Checking for leaked secrets or dependency vulnerabilities in the code generated by the agent.
- **Workflow Notifications**: Sending a Slack or Discord message when a long-running autonomous session completes.
- **Critical File Protection**: Blocking the agent from editing sensitive files (e.g., `.env`, `src/middleware.ts`) without explicit override.

## Strengths
- **Reliability**: Deterministic enforcement of rules that cannot be bypassed by prompt injection or model hallucination.
- **Automation**: Reduces the "babysitting" required for autonomous agents by automating the feedback loop.
- **Observability**: Provides clear, auditable logs of what happened before and after agent actions.

## Limitations
- **DevOps Overhead**: Requires maintaining a set of scripts and configurations alongside the main codebase.
- **Context Awareness**: Hooks are deterministic and may occasionally block valid agent actions if not configured with sufficient granularity.

## When to use it
- When you need repeatable, deterministic guardrails around agent execution.
- When integrating agents into a shared team environment with strict standards.
- When you want to automate the "feedback loop" (e.g., auto-running tests after a change).

## When not to use it
- When prompt instructions are sufficient and simplicity is the primary goal.
- During early-stage exploration where strict rules might hinder the agent's creative problem-solving.

## Getting started

### Configuration Setup
Claude hooks are typically defined in a project-level `claude_config.json`:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit",
        "handler": {
          "type": "command",
          "command": "node scripts/block-critical.js"
        }
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "handler": {
          "type": "command",
          "command": "npx prettier --write $FILEPATH"
        }
      }
    ]
  }
}
```

### Installation
Ensure your local environment has the necessary runtimes (Node.js, Python) to execute the hook scripts.

## CLI examples

### Executing Claude with Hooks
Hooks are automatically triggered by the `claude` CLI when a configuration is present:

```bash
# Start a session; hooks will run automatically based on config
claude

# Run a specific task with hook enforcement
claude "Refactor the authentication logic"

# Bypass hooks (use with caution)
claude --no-hooks "Quick fix for a non-critical file"
```

## API examples

### Implementing a Custom Hook (Node.js)
Hooks receive JSON context via `stdin` and must exit with code `0` to allow the agent to proceed.

```javascript
// scripts/block-critical.js
const fs = require('fs');

// Read tool-use context from Claude
const data = JSON.parse(fs.readFileSync('/dev/stdin', 'utf8'));
const blockedFiles = ['src/middleware.ts', '.env', 'package-lock.json'];

if (blockedFiles.some(file => data.filePath?.includes(file))) {
    console.error(`BLOCKED: Editing ${data.filePath} requires manual approval.`);
    process.exit(1); // Block Claude
}

process.exit(0); // Allow Claude
```

### Hook Metadata Extraction
You can use hooks to extract metadata about the agent's work for external dashboards.

```python
import sys
import json
import requests

def log_agent_action():
    # Read the PostToolUse payload
    context = json.load(sys.stdin)

    # Send to an internal observability tool
    requests.post("http://telemetry.local/agent-log", json={
        "tool": context['toolName'],
        "file": context.get('filePath'),
        "timestamp": context['timestamp']
    })

if __name__ == "__main__":
    log_agent_action()
```
