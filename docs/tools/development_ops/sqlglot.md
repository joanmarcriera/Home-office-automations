# SQLGlot

## What it is
SQLGlot is a no-dependency SQL parser, transporter, optimizer, and engine, written in Python. It can be used to format SQL or translate between different dialects like DuckDB, Presto, Spark, and Postgres. In July 2026, it is a core component for agentic SQL synthesis and validation.

## What problem it solves
Managing multiple SQL dialects across different database engines often leads to syntax errors and maintenance overhead. SQLGlot solves this by providing a unified AST (Abstract Syntax Tree) that allows for reliable translation, optimization, and safety auditing of SQL queries before execution.

## Where it fits in the stack
**Development Ops & Data Engineering** — It sits in the transformation and validation layer of the [Data Copilot](../../architecture/data-copilot-text-to-sql.md) architecture, ensuring that generated SQL is both syntactically correct and safe to execute.

## Typical use cases
- **Dialect Translation**: Converting a query from Spark SQL to Snowflake.
- **SQL Optimization**: Programmatically simplifying complex queries for better performance.
- **Safety Auditing**: Inspecting queries for prohibited operations (e.g., `DROP TABLE`) in agentic workflows.
- **Table/Column Lineage**: Extracting which tables and columns are used in a query.

## Strengths
- **No Dependencies**: Lightweight and easy to integrate into any Python project.
- **Extensive Dialect Support**: Supports over 20 different SQL dialects.
- **AST-based Manipulation**: Allows for deep inspection and modification of queries beyond simple regex.

## Limitations
- **Python Only**: Primary implementation is in Python, which may not suit all stacks.
- **Complexity**: Deep AST manipulation requires understanding of SQL structure.
- **Performance**: While fast for a Python parser, it may be slower than C-based parsers for massive batch processing.

## When to use it
- When you need to support multiple database backends with a single query generation logic.
- When you need to programmatically validate or "sanitize" SQL generated by LLMs.
- When you need to extract metadata (like table names) from arbitrary SQL strings.

## When not to use it
- For very simple SQL execution where a standard database driver is sufficient.
- In environments where Python is not available or supported.

## Getting started

### Installation
```bash
pip install sqlglot
```

### Hello World
```python
import sqlglot
sql = "SELECT left(x, 2) FROM table"
print(sqlglot.transpile(sql, read="duckdb", write="spark")[0])
# SELECT SUBSTR(x, 1, 2) FROM table
```

## CLI examples
SQLGlot provides a CLI for quick transpilation and formatting:

```bash
# Transpile a query from one dialect to another
sqlglot-transpile "SELECT * FROM table" --read duckdb --write spark

# Format a SQL file
sqlglot-format query.sql

# Check for syntax errors in a query
sqlglot-check "SELECT * FROM table" --dialect postgres
```

## API examples
Using the Python API for advanced manipulation:

```python
from sqlglot import parse_one, exp

# Parse a query into an AST
expression = parse_one("SELECT a, b FROM table WHERE c > 1")

# Extract all column names
columns = [column.name for column in expression.find_all(exp.Column)]
print(columns) # ['a', 'b', 'c']

# Change the table name
expression.find(exp.Table).set("this", "new_table")
print(expression.sql()) # SELECT a, b FROM new_table WHERE c > 1
```
