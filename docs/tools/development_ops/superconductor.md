# Superconductor

## What it is
Superconductor is a multiplayer, cloud-native AI workspace designed for teams to orchestrate multiple AI agents in parallel. It provides a centralized environment where developers, PMs, and designers can collaborate with agents like [Claude Code](claude-code.md), [Aider](aider.md), and [Codex](codex.md) across shared projects with live browser previews and integrated sandboxing.

## What problem it solves
It eliminates the "single-agent bottleneck" by allowing multiple agents to work on different tickets or components simultaneously. Superconductor also solves the collaboration gap in agentic coding, providing a shared state where team members can review agent progress, debug in real-time, and manage permissions and API costs centrally.

## Where it fits in the stack
**Development & Ops / [Orchestration](../orchestration/index.md)**. It acts as a multiplayer control plane that sits above individual AI coding agents and provides the infrastructure (sandboxes, previews, network isolation) for them to operate.

## Typical use cases
- **Parallel Sprint Execution**: Launching five different agents to handle five separate GitHub issues simultaneously.
- **Collaborative Debugging**: Multiple developers joining an agent's session to guide it through a complex fix.
- **PM/Designer Review**: Non-technical stakeholders reviewing UI changes in live previews generated by an agent.
- **Network-Isolated Coding**: Using "Network Sandboxing" to allow agents to fetch documentation while blocking access to sensitive internal domains.

## Strengths
- **Multiplayer-First**: Real-time synchronization of code, terminal, and agent chat across team members.
- **Agent Agnostic**: Supports running various frontier agents ([Claude Code](claude-code.md), [Aider](aider.md), etc.) within the same workspace.
- **Live Previews**: Instant, waking-on-demand browser previews for web applications.
- **Network Sandboxing**: Granular control over which external domains an agent can access during execution.
- **Mobile Friendly**: Ability to kick off and review agent work from a smartphone.

## Limitations
- **Latency**: Cloud-based sandboxes may have slight startup delays compared to local execution.
- **Cost**: Managed infrastructure and parallel agent runs can consume credits rapidly if not monitored.
- **Complexity**: Requires workspace configuration to match local development environments for complex builds.

## When to use it
- For high-velocity teams needing to scale development output through parallel agents.
- When you want to provide a "safe" environment for agents to run with network and filesystem guardrails.
- For projects where multi-stakeholder review of AI-generated code is part of the workflow.

## When not to use it
- For simple, single-file edits where local [Aider](aider.md) or [Cursor](cursor.md) usage is faster.
- In environments with zero-cloud-access policies that require 100% local infrastructure (use [Mentat](mentat.md) or [Ollama](../../services/ollama.md) instead).

## Getting started

### Installation
Superconductor is primarily accessed via the web, but includes a CLI for local synchronization and workspace management:

```bash
curl -fsSL https://superconductor.com/install.sh | bash
```

### Authentication
Login to your team workspace:

```bash
superconductor login
```

### Initializing a Project
Connect your local repository to a Superconductor cloud workspace:

```bash
superconductor init
```

## CLI examples

### Launching an Agent Session
Start a new parallel agent to work on a specific task:

```bash
superconductor agent start "Implement OAuth2" --agent claude-code
```

### Managing Sandboxes
List active cloud environments and their status:

```bash
superconductor workspace list
```

### Synchronizing Files
Pull the latest agent-generated changes from the cloud workspace to your local branch:

```bash
superconductor sync pull
```

## API examples

### Triggering Work from External Signals
Superconductor provides a REST API to launch agents from external triggers (e.g., a specific tag on a GitHub issue):

```bash
curl -X POST https://api.superconductor.com/v1/workstreams \
  -H "Authorization: Bearer $API_KEY" \
  -d '{
    "task": "Fix security vulnerability in auth.ts",
    "agent": "claude-4-8-opus",
    "sandbox": "production-mirror"
  }'
```
