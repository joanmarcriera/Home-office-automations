# Bionic Shell

## What it is
Bionic Shell is an open-source, security-focused shell environment and CLI agent harness released in August 2026. Designed for agentic command execution and system administration safety, Bionic Shell uses active Abstract Syntax Tree (AST) parsing, real-time command inspection, sandboxed dry-runs, and deterministic permission policies to prevent catastrophic destructive commands (e.g., recursive unconstrained file deletions or network exfiltration) generated by AI coding assistants. As of early 2027, Bionic Shell integrates natively with **FastMCP 3.1** and the **MCP 3.0 Task Protocol**, providing a secure shell runtime for agents powered by [Claude 5.6](../ai_knowledge/claude-macos.md), [GPT-5.6](../ai_knowledge/chatgpt.md), or [Qwen 3.8](../ai_knowledge/qwen.md).

## What problem it solves
Autonomous software development and shell agents frequently execute terminal commands on developer workstations or CI/CD runner pipelines. Unconstrained LLM shell tool use can cause accidental data loss, corrupted configuration files, or unintended remote network calls. Bionic Shell introduces an inline safety boundary that intercepts, sanitizes, evaluates, and verifies shell commands before execution, requiring human confirmation only for high-risk system state mutations.

## Where it fits in the stack
**Development & Developer Operations / Agent Harness & Shell Safety.** Bionic Shell acts as the protective execution sandbox layer sitting between autonomous LLM agent frameworks and the host operating system kernel.

## Typical use cases
- **Protected Autonomous Agent Loops**: Executing multi-step terminal workflows using agent harnesses like [OmO](opencode.md) or custom MCP servers without risk of runaway system destruction.
- **Interactive Developer Shell Interception**: Guarding developer shell sessions against dangerous copy-pasted or AI-generated commands.
- **CI/CD Sandbox Hardening**: Restricting shell operations in continuous integration pipelines to pre-validated command patterns and strict file subtrees.
- **Audit-Logged Admin Operations**: Recording detailed AST trace logs and execution diffs for corporate compliance auditing.

## Strengths
- **AST-Based Command Inspection**: Parses complex bash scripts and chained pipeline commands into structured syntax trees prior to execution.
- **FastMCP 3.1 Protocol Integration**: Exposes safe tool interfaces directly to local and cloud agent runtimes.
- **Configurable Risk Policies**: Allows granular definition of ALLOW, WARN, and BLOCK rules based on file paths, flags, and system calls.
- **Dry-Run Simulation**: Simulates file system mutations in an ephemeral container before applying changes to the real host workspace.

## Limitations
- **Latency Overhead**: AST parsing and policy evaluation add 10ms–30ms of latency per executed command.
- **Complex Script Parsing**: Obfuscated or deeply nested shell scripts may trigger false-positive warnings requiring manual override.
- **Platform Parity**: Full sandbox container isolation features are optimized for Linux and macOS, with Windows WSL2 required for full isolation.

## When to use it
- When granting autonomous AI agents terminal execution access to local codebases or production machines.
- When running enterprise developer environments with strict audit and security compliance mandates.
- As a protective shell harness for local CLI agents and MCP servers.

## When not to use it
- For high-frequency, low-latency micro-benchmark scripting where sub-millisecond shell execution is mandatory.
- When working in completely isolated, read-only ephemeral Docker containers where accidental host mutations are impossible.

## Getting started

### Installation
```bash
pip install bionic-shell
```

### Basic Usage
```bash
# Launch interactive Bionic Shell environment with default safety policy
bionic-shell --policy strict
```

## CLI examples

### 1. Evaluate Command Safety Dry-Run
```bash
bionic-shell eval --command "rm -rf ./build/*.tmp && git status"
```

### 2. Launch FastMCP 3.1 Tool Server
```bash
bionic-shell serve-mcp --port 8080 --workspace /home/user/project
```

## API examples

### Programmatic Python Integration with Pydantic v2 Command Safety Validation
The following example demonstrates invoking Bionic Shell programmatically to evaluate a shell command string and strictly validate the safety inspection report using **Pydantic v2**.

```python
import sys
from typing import List, Literal, Optional
from pydantic import BaseModel, Field, ValidationError

class RiskAssessment(BaseModel):
    risk_level: Literal["LOW", "MEDIUM", "HIGH", "CRITICAL"]
    detected_actions: List[str] = Field(..., description="List of mutating or risky operations identified")
    requires_approval: bool = Field(..., description="Whether human confirmation is mandated")

class CommandEvaluationReport(BaseModel):
    raw_command: str
    parsed_ast: str = Field(..., description="Normalized Abstract Syntax Tree representation")
    assessment: RiskAssessment
    policy_verdict: Literal["ALLOW", "WARN", "BLOCK"]

def evaluate_shell_command(command: str) -> Optional[CommandEvaluationReport]:
    # Simulated Bionic Shell AST inspection logic
    is_destructive = any(kw in command for kw in ["rm -rf", "dd", "mkfs", "chmod -R 777"])

    risk_level = "CRITICAL" if is_destructive else "LOW"
    verdict = "BLOCK" if is_destructive else "ALLOW"

    mock_report = {
        "raw_command": command,
        "parsed_ast": f"(CallExpr (Command '{command.split()[0]}') (Args ...))",
        "assessment": {
            "risk_level": risk_level,
            "detected_actions": ["RECURSIVE_DELETE", "UNCONSTRAINED_MUTATION"] if is_destructive else ["READ_STATUS"],
            "requires_approval": is_destructive
        },
        "policy_verdict": verdict
    }

    try:
        # Validate output payload with Pydantic v2
        return CommandEvaluationReport.model_validate(mock_report)
    except ValidationError as ve:
        print(f"Pydantic Validation Error: {ve}", file=sys.stderr)
        return None

if __name__ == "__main__":
    print("Testing Bionic Shell safety inspection pipeline...")

    # Test dangerous command
    dangerous_cmd = "rm -rf /var/log/*"
    report = evaluate_shell_command(dangerous_cmd)

    if report:
        print("Bionic Shell Command Evaluation validated successfully via Pydantic v2:")
        print(f"  Command: {report.raw_command}")
        print(f"  Verdict: {report.policy_verdict}")
        print(f"  Risk Level: {report.assessment.risk_level}")
        print(f"  Requires Approval: {report.assessment.requires_approval}")
```
